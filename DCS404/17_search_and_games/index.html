Principles of AI: Search and Games

DCS 404 · Data Science and Machine Learning

Every other module in this course is about learning from data: fit a line, grow a tree, cluster some points. This one isn't. Here we build programs that act intelligently with no training data at all. They play Tic-Tac-Toe without ever losing, find the shortest way through a maze, and beat a random Connect Four player every time. None of them learn anything. They search: they look at the possible futures and pick the move that leads to the best one.

That's the first big lesson of this module, and of Chapter 1 of the course textbook: machine learning is one way to get artificial intelligence, not the only way. Search, rules, and heuristics were the main way to build AI for decades. They still run inside route planners, game engines, schedulers, and puzzle solvers today, and they still sit next to learned models in systems like AlphaGo.

This notebook covers the Week 3 reading, Artificial Intelligence and Machine Learning Fundamentals (Nagy, 2018), Chapter 1 — Principles of AI and Chapter 2 — AI with Search Techniques and Games. Everything is built from scratch in plain Python, so you can see exactly how each algorithm works.

1. What is AI, and how is it different from machine learning?

The textbook starts with three definitions worth knowing by heart:

Artificial Intelligence is a science that's used to construct intelligence using hardware and software solutions.

Machine learning is a field of study concerned with giving computers the ability to learn without being explicitly programmed. (Arthur Samuel, 1959)

A computer program is said to learn from experience \(E\) with respect to a task \(T\) and a performance measure \(P\), if its performance on \(T\), as measured by \(P\), improves with experience \(E\). (Tom Mitchell, 1997)

Mitchell's definition is the useful one, because you can check it. Spam filtering: \(T\) = label emails, \(P\) = accuracy, \(E\) = a pile of emails humans have already labelled. Every model in the later modules of this course fits that pattern.

Now the key point. You can build AI without machine learning. If you hard-code rules, or search through possible futures, your program can act intelligently with no experience \(E\) at all. All of this module works that way:

A self-driving car has to sense other cars (computer vision), predict where they'll go (statistics), plan a route (graph theory and search), and move the wheels (control theory and robotics). The Turing test

Alan Turing proposed testing intelligence by conversation. A judge chats by text with a human and a machine. If the judge can't reliably tell which is which, the machine passes. The textbook (2018) predicted this wouldn't happen until "the late 2020s". That prediction has aged fast. In a 2025 study (Jones & Bergen), judges picked GPT-4.5 as the human 73% of the time when it was prompted to adopt a persona. Large language models have changed this part of the field more than any other since the book was written. The Total Turing test, which adds vision and physical movement, is still far off.

Two kinds of reasoning, two kinds of learning

  • Classification works out what category something belongs to ("Jane is female and a parent, so Jane is a mother"). Prediction estimates something from patterns ("someone who buys organic milk is more likely to buy organic yoghurt").
  • Supervised learning learns from labelled examples (Regression, Logistic Regression, Decision Trees, KNN). Unsupervised learning finds structure without labels (K-Means). Both get full modules later in the course.

2. Intelligent agents

The central object in AI (and in this module) is the agent. The textbook defines an intelligent agent as something that:

  • is autonomous,
  • observes its surroundings through sensors,
  • acts on its environment through actuators, and
  • directs its activity toward a goal.

Put simply: an agent is a function from what it perceives to what it does. Let's write one. Here is the classic vacuum world: two rooms, A and B, each either clean or dirty. The vacuum's sensors tell it which room it's in and whether that room is dirty. Its actuators can Suck, or move Left / Right.

def reflex_vacuum_agent(percept):
    '''A simple reflex agent: the action depends only on the current percept.'''
    location, is_dirty = percept
    if is_dirty:
        return "Suck"
    return "Right" if location == "A" else "Left"

def run_vacuum_world(agent, dirt, location="A", steps=6):
    dirt = dict(dirt)                                   # don't mutate the caller's dict
    score = 0
    for t in range(steps):
        percept = (location, dirt[location])            # sensors
        action = agent(percept)                         # the agent decides
        if action == "Suck" and dirt[location]:         # actuators change the world
            dirt[location] = False
            score += 10                                 # reward for cleaning
        elif action in ("Left", "Right"):
            location = "A" if action == "Left" else "B"
            score -= 1                                  # small cost for moving
        print(f"t={t}  percept={percept!s:<14} action={action:<6} world={dirt}")
    print(f"Performance score: {score}")

Both rooms are clean after three steps, and the agent never "learned" anything. Its designer wrote the rules in advance. Two ideas from this toy come back in every later section:

  1. Performance measure. We judged the agent by a score (+10 per clean, −1 per move). The textbook calls this the "carrot and stick": good actions are rewarded and bad ones punished. A game AI's goal is the same in principle: get the highest score, where winning is the top score.
  2. The agent wastes moves. After both rooms are clean it keeps going back and forth (Left, Right, …), because a reflex agent can't think ahead. Agents that look ahead at the consequences of their actions are what the rest of this module builds.

4. Problems as search: breadth-first and depth-first search

To make an agent look ahead, we describe the problem as a state space:

  • an initial state, where we start;
  • a successor function succ(state), the states reachable in one action;
  • a goal test, which says whether we're done.

Starting at the initial state and applying succ over and over builds a search tree. The root is the start, each edge is an action, and leaves are states with no successors. Search algorithms differ only in the order they visit the tree.

The book's toy problem: start at 1. Each step adds 1 or 2. Stop at 5.

def succ(node):
    value, depth = node
    if value == 5:
        return []                                   # goal: a leaf
    if value == 4:
        return [(5, depth + 1)]                     # can't jump past 5
    return [(value + 1, depth + 1), (value + 2, depth + 1)]

root = (1, 1)   # (value, depth)

def bfs_tree(root):
    to_visit = deque([root])          # a QUEUE: first in, first out
    visited = []
    while to_visit:
        node = to_visit.popleft()
        visited.append(node)
        to_visit.extend(succ(node))
    return visited

def dfs_tree(root):
    to_visit = [root]                 # a STACK: last in, first out
    visited = []
    while to_visit:
        node = to_visit.pop()
        visited.append(node)
        to_visit.extend(succ(node))
    return visited

bfs_order, dfs_order = bfs_tree(root), dfs_tree(root)
print("BFS visits (value, depth):", bfs_order)
print("DFS visits (value, depth):", dfs_order)

The only difference between the two functions is popleft() (queue) versus pop() (stack). It's easier to see on the tree itself. The number in each node's corner is the order it was visited:

def build_tree(node, path=()):
    '''Return a nested dict {'node': (value, depth), 'id': path, 'children': [...]}.'''
    return {"node": node, "id": path,
            "children": [build_tree(c, path + (i,)) for i, c in enumerate(succ(node))]}

def layout(tree, x=0.0, positions=None):
    '''Assign x positions so leaves are evenly spaced; returns (positions, next_free_x).'''
    positions = {} if positions is None else positions
    if not tree["children"]:
        positions[tree["id"]] = (x, -tree["node"][1]); return positions, x + 1
    xs = []
    for ch in tree["children"]:
        positions, x = layout(ch, x, positions); xs.append(positions[ch["id"]][0])
    positions[tree["id"]] = (sum(xs) / len(xs), -tree["node"][1])
    return positions, x

def visit_rank(tree, order_fn):
    '''Map each tree-node id to its visit number under BFS/DFS (same traversal, on ids).'''
    ranks, frontier = {}, deque([tree]) if order_fn == "bfs" else [tree]
    while frontier:
        t = frontier.popleft() if order_fn == "bfs" else frontier.pop()
        ranks[t["id"]] = len(ranks) + 1
        frontier.extend(t["children"])
    return ranks

def draw_tree(tree, ranks, ax, title):
    pos, _ = layout(tree)
    def edges(t):
        for ch in t["children"]:
            (x0, y0), (x1, y1) = pos[t["id"]], pos[ch["id"]]
            ax.plot([x0, x1], [y0, y1], color="grey", lw=1, zorder=1); edges(ch)
    edges(tree)
    def nodes(t):
        x, y = pos[t["id"]]; v = t["node"][0]
        ax.scatter(x, y, s=520, color="tab:green" if v == 5 else "tab:blue", zorder=2)
        ax.text(x, y, str(v), ha="center", va="center", color="white", fontweight="bold", zorder=3)
        ax.text(x + 0.22, y + 0.22, str(ranks[t["id"]]), fontsize=8, color="tab:red", zorder=3)
        for ch in t["children"]: nodes(ch)
    nodes(tree)
    ax.set_title(title); ax.axis("off")

fig, axes = plt.subplots(1, 2, figsize=(12, 4.2))
draw_tree(tree, visit_rank(tree, "bfs"), axes[0], "BFS: level by level")
draw_tree(tree, visit_rank(tree, "dfs"), axes[1], "DFS: dive deep first")
plt.suptitle("Same tree, different visiting order (red = visit number, green = goal value 5)", y=1.02)
plt.tight_layout(); plt.show()

  • BFS visits level by level, so the first goal it reaches is the shallowest one. Here that's 5 at depth 3 (1 → 3 → 5). For problems where every step costs the same, BFS finds a shortest path.
  • DFS dives straight down one branch first. It uses little memory but doesn't guarantee the shortest path. In a huge tree like chess it can get lost down one very deep branch.

Trees vs graphs. If two different paths can reach the same state (and in Tic-Tac-Toe they can), you should keep a visited set and skip states you've already seen. Otherwise you do the same work again and again. Section 8 shows exactly how much that costs.

5. The state space of Tic-Tac-Toe

Two players take turns on a 3×3 board. X moves first. Three in a row, column, or diagonal wins. Like the book, we store the board as a 9-character string, cells indexed like this:

 0 | 1 | 2
---+---+---
 3 | 4 | 5
---+---+---
 6 | 7 | 8

Our AI plays X and moves first. The opponent plays O.

EMPTY, AI, OPP = ".", "X", "O"
LINES = [(0, 1, 2), (3, 4, 5), (6, 7, 8),      # rows
         (0, 3, 6), (1, 4, 7), (2, 5, 8),      # columns
         (0, 4, 8), (2, 4, 6)]                 # diagonals

def other(sign):
    return OPP if sign == AI else AI

def winner(board):
    '''Return 'X' or 'O' if someone has three in a line, else EMPTY.'''
    for i, j, k in LINES:
        if board[i] == board[j] == board[k] != EMPTY:
            return board[i]
    return EMPTY

def is_over(board):
    return winner(board) != EMPTY or EMPTY not in board

def all_moves(board, sign):
    '''The successor function: every board reachable by `sign` placing one mark.'''
    return [board[:i] + sign + board[i + 1:] for i, c in enumerate(board) if c == EMPTY]

def print_board(board):

How big is the game? (textbook Exercise 2)

A rough upper bound: the first player has 9 choices, the second 8, then 7, … so at most \(9! = 362{,}880\) move sequences. Many games end early with a win, so the true number is smaller. We don't have to estimate it, though. A short recursive search can count every possible game exactly:

def count_games(board=EMPTY * 9, turn=AI):
    '''Exhaustively play out every legal game; return a Counter of outcomes.'''
    w = winner(board)
    if w != EMPTY:
        return Counter({w: 1})
    if EMPTY not in board:
        return Counter({"draw": 1})
    total = Counter()
    for nxt in all_moves(board, turn):
        total += count_games(nxt, other(turn))
    return total

t0 = time.time()
outcomes = count_games()
print(f"9! upper bound:       {math.factorial(9):,}")

print(f"  X (first player) wins: {outcomes['X']:,}")
print(f"  O (second player) wins: {outcomes['O']:,}")
print(f"  draws:                  {outcomes['draw']:,}")

def states_per_depth():
    level, sizes = [EMPTY * 9], [1]
    for step in range(9):
        sign = AI if step % 2 == 0 else OPP
        level = [n for b in level for n in all_moves(b, sign)]
        sizes.append(len(level))
        level = [b for b in level if winner(b) == EMPTY]   # finished games stop growing
    return sizes

No computer can list every chess game. This explosion is why the rest of the module exists. Every technique that follows is a way to avoid looking at most of this tree.

⚠️ Textbook check: why the book says 266,073. The book's Activity 1 reports 266,073 games, which is more than the true 255,168. That's impossible, and its own note quotes the correct figure. The cause is its filter_wins function, which calls list.remove() while looping over the same list. Removing an item shifts the rest of the list left, so the loop skips whatever comes next. If that next board was also a finished game, it never gets filtered out, and its "children" get counted too. A three-line demo:

numbers = [1, 2, 2, 3]
for n in numbers:
    if n == 2:
        numbers.remove(n)      # mutating the list we're iterating over...
print(numbers)                 # ...leaves a 2 behind: the second 2 was skipped

numbers = [1, 2, 2, 3]
numbers = [n for n in numbers if n != 2]   # the safe way: build a new list
print(numbers)

A random player (textbook Exercise 3)

The simplest possible agent picks any empty cell at random. Below, two random players face each other 10,000 times. The book's version asks for the human's move with input(). To play yourself, set INTERACTIVE = True in Setup and run the play_vs cell at the end of Section 9.

def random_policy(board, sign):
    return rng.choice(all_moves(board, sign))

def play_game(policy_x, policy_o, start=EMPTY * 9):
    '''Play one game; return the final board.'''
    board, turn = start, AI
    while not is_over(board):
        board = (policy_x if turn == AI else policy_o)(board, turn)
        turn = other(turn)
    return board

def tournament(policy_x, policy_o, n=1000):
    results = Counter()
    for _ in range(n):
        w = winner(play_game(policy_x, policy_o))
        results["X wins" if w == AI else "O wins" if w == OPP else "draw"] += 1
    return {k: results[k] for k in ("X wins", "O wins", "draw")}

6. Teaching the agent with rules (textbook Exercise 4, Activities 2–3)

We'll improve the X player in three steps, adding one rule at a time. After each step we check it in two ways:

  1. Exhaustive check. Play X's policy against every possible O reply, and count every possible game. This is a guarantee: if no game in this count is a loss, X can never lose.
  2. Tournament. Play 1,000 games against a random O, the kind of opponent you'd actually meet.

    return winning[:1] or options

def moves_win_block(board, sign):
    winning = moves_win(board, sign)
    if winner(winning[0]) == sign:
        return winning
    safe = [b for b in winning if not opponent_can_win(b, other(sign))]
    return safe or winning                      # if nothing is safe, we've lost anyway

    return moves_win_block(board, sign)

The book sums up the tricks we used to shrink the state space. Each one comes back later in this module:

  1. Empirical simplification: hard-code moves you know are good (the corner opening).
  2. Symmetry: the four corners are equivalent, because rotating the board turns one into another.
  3. Merging permutations: moves A, X, B and B, X, A reach the same board, so explore it once.
  4. Forced moves for us: if we can complete a line, or must block one, there's only one move to consider.
  5. Forced moves for the opponent: assume they'll make the obvious winning or blocking move.
  6. Random move: a last resort when we can't search.

Hand-written rules worked here, but someone had to find them. That was easy for Tic-Tac-Toe and is hopeless for chess. The next step is to let the program score positions and search for good moves itself.

7. Heuristics: educated guesses that guide search

BFS and DFS are uninformed searches. They treat every branch the same and know nothing about the problem. An informed search uses a heuristic, a function that makes an educated guess about how good a state or move is. The book lists three kinds of guess:

  • how useful a move is,
  • how good a game state is for a player,
  • how far a state is from the goal (for pathfinding).

The book uses utility and cost as opposites: maximising utility is the same as minimising cost.

Heuristic 1 — evaluate only finished games

\(+1\) if the AI has won, \(-1\) if it has lost, \(0\) otherwise. It's always correct, but almost always zero: nobody can win in fewer than 5 moves, so it tells an opening player nothing. A heuristic is only useful if it can tell non-final positions apart.

Heuristic 2 — score every empty cell (textbook Exercise 5)

Look at all 8 lines. For each line, add points to its empty cells:

Pattern in a line Points to each empty cell in it Meaning
two X + one empty +1000 win now
two O + one empty +100 must block
one X + two empty +10 build a threat
three empty +1 keep options open

Why powers of ten? A cell sits on at most 4 lines, so lower-tier points can never add up to beat one higher-tier rule (\(4 \times 10 < 100\)). Winning always beats blocking, and blocking always beats building.

Admissible, optimal, complete

Three properties people check on a heuristic:

  • Admissible: it never overestimates the true cost to the goal. (It may underestimate.) This is the property A* needs to guarantee a shortest path (Section 8).
  • Optimal: the search it guides always finds the best solution.
  • Complete: the search always finds a solution if one exists.

Our Tic-Tac-Toe heuristic is not optimal: as O it picks moves that lose, while a perfect player would never lose (Section 9). For pathfinding, though, there are simple heuristics that are admissible: straight-line (Euclidean) distance and Manhattan distance (horizontal + vertical steps). Which one is admissible depends on how you're allowed to move:

We'll compare four searches. All of them follow parent pointers back from the goal to rebuild the path, and all of them count how many cells they expand (take off the frontier and examine). That count is the work the search did.

def reconstruct(parent, node):
    path = [node]
    while parent[node] is not None:
        node = parent[node]; path.append(node)
    return path[::-1]

def bfs(start, end, nbrs=neighbours):
    frontier, parent, expanded = deque([start]), {start: None}, []
    while frontier:
        node = frontier.popleft(); expanded.append(node)
        if node == end:
            return reconstruct(parent, node), expanded
        for s in nbrs(node):
            if s not in parent:                 # visited check: never queue a cell twice
                parent[s] = node; frontier.append(s)
    return None, expanded

def best_first(start, end, h, use_cost_so_far, nbrs=neighbours):
    '''use_cost_so_far=False -> greedy best-first (f = h);  True -> A* (f = g + h).'''
    g, parent, closed, expanded = {start: 0}, {start: None}, set(), []
    frontier, tie = [(h(start, end), 0, start)], 0          # (priority, tie-breaker, node)
    while frontier:
        _, _, node = heapq.heappop(frontier)
        if node in closed:
            continue                                         # stale duplicate entry
        closed.add(node); expanded.append(node)
        if node == end:
            return reconstruct(parent, node), expanded
        for s in nbrs(node):
            new_g = g[node] + 1
            if s not in closed and new_g < g.get(s, math.inf):
                g[s], parent[s] = new_g, node
                tie += 1
                f = (new_g if use_cost_so_far else 0) + h(s, end)
                heapq.heappush(frontier, (f, tie, s))
    return None, expanded

  • Greedy best-first (priority = \(h\) only) rushes toward the goal. It examines fewer cells, but returns a 17-step path, not the shortest. It only ever asks "which cell looks closest to G?" and never "how far have I already walked?", so it commits to the route that looked good early on.
  • A* ranks cells by $\(f(n) = \underbrace{g(n)}_{\text{steps taken so far}} + \underbrace{h(n)}_{\text{estimated steps left}}\)$ and returns the optimal 15-step path, guaranteed, because both heuristics are admissible on a 4-direction grid. Why does admissibility guarantee the shortest path? When A* takes the goal off the frontier, its \(f = g\) is an exact path length, because \(h(\text{goal}) = 0\). Every other node still on the frontier has \(f \ge\) that value, and since \(h\) never overestimates, \(f\) is a lower bound on any path through that node. So no path left unexplored can be shorter.

⚠️ Textbook checks for this section. 1. The book describes A* as storing children "in the order of their distance from the goal". That's greedy search, the method that just returned a 17-step path. A* orders by \(g + h\). 2. The book's BFS needs 110 steps because it has no shared visited set: the same cell gets queued again and again by different neighbours. With a visited check (above), BFS expands at most one entry per free cell, 47 here. 3. The book's astar removes old frontier entries with a list comprehension, which breaks the heap ordering that heapq relies on. Pushing duplicates and skipping stale ones on pop (our closed check) is the standard fix.

9. Two-player games: the Minimax algorithm

Pathfinding has a single agent. In a game, an opponent moves between your turns, trying to make things as bad for you as possible. We can't just pick the branch with the best outcome, because the opponent decides half of the branches.

Minimax assumes the opponent plays perfectly and works backwards from the leaves:

  • At our turn (MAX), choose the child with the highest value.
  • At their turn (MIN), they choose the child with the lowest value.
  • At a leaf (game over, or our search depth runs out), use a static evaluation, i.e. a heuristic.
\[ \text{minimax}(s) = \begin{cases} \text{utility}(s) & \text{if } s \text{ is terminal or depth} = 0\\ \max_{s' \in \text{succ}(s)} \text{minimax}(s') & \text{if it's MAX's turn}\\ \min_{s' \in \text{succ}(s)} \text{minimax}(s') & \text{if it's MIN's turn} \end{cases} \]

Try it on a small tree first. The leaves are heuristic scores from MAX's point of view. Values move up the tree: MAX levels take the larger child value, MIN levels take the smaller.

# A depth-3 game tree: MAX -> MIN -> MAX -> leaves
TOY = [[[3, 12], [8, 2]],
       [[4, 6], [14, 5]],
       [[1, 9], [2, 7]]]

def toy_minimax(node, maximizing, trace):
    if isinstance(node, int):
        trace.append(node); return node
    vals = [toy_minimax(ch, not maximizing, trace) for ch in node]
    return max(vals) if maximizing else min(vals)

trace = []

def draw_game_tree(tree, ax, values_fn, pruned=frozenset(), title=""):
    '''Draw a nested-list tree; values_fn(path) gives the number to print at each node.'''
    pos, leaves = {}, [0]
    def place(node, path, depth):
        if isinstance(node, int):
            pos[path] = (leaves[0], -depth); leaves[0] += 1; return
        for i, ch in enumerate(node):
            place(ch, path + (i,), depth + 1)
        xs = [pos[path + (i,)][0] for i in range(len(node))]

10. Alpha-beta pruning: same answer, a fraction of the work

Look back at the toy tree. Once the left branch is worth 8 to us, consider the middle MIN node. As soon as its first child comes back worth 6, we know the MIN node is worth at most 6, because MIN will never pick anything higher. 6 < 8, so we'd never choose this branch, whatever its other children are worth. We can skip them. That's a cut-off.

Alpha-beta tracks two bounds as it searches:

  • \(\alpha\): the best value MAX can already guarantee on the path so far (starts at \(-\infty\)),
  • \(\beta\): the best value MIN can already guarantee (starts at \(+\infty\)).

As soon as \(\alpha \ge \beta\), the rest of that node's children can't change the decision, so we stop.

def toy_alphabeta(node, maximizing, alpha, beta, path, visited):
    visited.add(path)
    if isinstance(node, int):
        return node
    best = -math.inf if maximizing else math.inf
    for i, ch in enumerate(node):
        v = toy_alphabeta(ch, not maximizing, alpha, beta, path + (i,), visited)
        if maximizing:
            best = max(best, v); alpha = max(alpha, best)
        else:
            best = min(best, v); beta = min(beta, best)
        if alpha >= beta:
            break                                   # cut-off: skip the remaining children
    return best

11. Negamax: one branch instead of two

The MAX and MIN branches in alphabeta mirror each other. The book cites the DRY principle (Don't Repeat Yourself): code written twice is twice as likely to contain a bug. In a zero-sum game, a position worth \(+v\) to one player is worth \(-v\) to the other, so

\[\min(a, b) = -\max(-a, -b).\]

Negamax always scores from the point of view of the player about to move, and flips the sign when it passes the turn:

\[\text{negamax}(s) = \max_{s' \in \text{succ}(s)} \big(-\text{negamax}(s')\big).\]
def negamax(board, turn, alpha=-math.inf, beta=math.inf):
    '''Value of `board` for the player `turn` who is about to move (with alpha-beta).'''
    NODES[0] += 1
    if is_over(board):
        score_for_x = terminal_score(board)
        return score_for_x if turn == AI else -score_for_x
    best = -math.inf
    for b in all_moves(board, turn):
        best = max(best, -negamax(b, other(turn), -beta, -alpha))
        alpha = max(alpha, best)
        if alpha >= beta: break
    return best

12. Connect Four: when you can't search to the end (textbook Activity 4)

Connect Four: 7 columns × 6 rows. (The book says "seven cells high"; the standard board, and the book's own solution code, use 6.) You drop a token into a column, it falls to the lowest empty cell, and four in a row in any direction wins. The game has about \(4.5 \times 10^{12}\) legal positions. That's tiny next to chess, but still far too many to search to the end in Python.

So we use what real game engines use: depth-limited Negamax with alpha-beta, plus a heuristic evaluation for positions where the search stops before the game ends. Our heuristic looks at every 4-cell "window" (all 69 possible lines of four):

Window contains Score (for the player to move)
3 of mine + 1 empty +5
2 of mine + 2 empty +2
3 of the opponent's + 1 empty −4
each of my tokens in the centre column +3 (the centre is on the most windows) 
C4_ROWS, C4_COLS = 6, 7

def c4_new():
    return np.zeros((C4_ROWS, C4_COLS), dtype=int)       # 0 empty, 1 = player 1, 2 = player 2

def c4_moves(board):
    return [c for c in range(C4_COLS) if board[0, c] == 0]

def c4_drop(board, col, player):
    b = board.copy()
    row = max(r for r in range(C4_ROWS) if b[r, col] == 0)    # gravity: lowest empty cell
    b[row, col] = player
    return b

# All 69 windows of four cells, precomputed once (the book's "winning tuples")
WINDOWS = []
for r in range(C4_ROWS):
    for c in range(C4_COLS):
        for dr, dc in ((0, 1), (1, 0), (1, 1), (-1, 1)):       # right, down, diagonal down, diagonal up
            cells = [(r + k * dr, c + k * dc) for k in range(4)]
            if all(0 <= rr < C4_ROWS and 0 <= cc < C4_COLS for rr, cc in cells):
                WINDOWS.append(tuple(np.array(cells).T))
print(f"{len(WINDOWS)} winning lines of four on a 6x7 board")

def c4_wins(board, player):
    return any((board[w] == player).all() for w in WINDOWS)

def c4_evaluate(board, player):
    opp, score = 3 - player, 3 * int((board[:, C4_COLS // 2] == player).sum())
    for w in WINDOWS:
        cells = board[w]
        mine, theirs, empty = (cells == player).sum(), (cells == opp).sum(), (cells == 0).sum()
        if mine == 3 and empty == 1:     score += 5
        elif mine == 2 and empty == 2:   score += 2
        if theirs == 3 and empty == 1:   score -= 4
    return score

def c4_negamax(board, depth, alpha, beta, player):
    opp = 3 - player
    if c4_wins(board, opp):
        return -1_000_000 - depth          # opponent just won: very bad; losing later is less bad
    moves = c4_moves(board)
    if not moves:
        return 0                           # board full: draw
    if depth == 0:
        return c4_evaluate(board, player)  # out of search budget: trust the heuristic
    best = -math.inf
    for col in sorted(moves, key=lambda c: abs(c - 3)):   # try centre columns first -> more cut-offs
        best = max(best, -c4_negamax(c4_drop(board, col, player), depth - 1, -beta, -alpha, opp))
        alpha = max(alpha, best)
        if alpha >= beta: break
    return best

def c4_ai(depth):
    def policy(board, player):
        scored = [(-c4_negamax(c4_drop(board, c, player), depth - 1, -math.inf, math.inf, 3 - player), c)
                  for c in c4_moves(board)]
        best = max(s for s, _ in scored)
        return rng.choice([c for s, c in scored if s == best])
    return policy

def c4_random(board, player):
    return rng.choice(c4_moves(board))

def c4_show(board):
    print("\n".join(" ".join(".XO"[v] for v in row) for row in board))
    print(" ".join(str(c) for c in range(C4_COLS)))

15. If you remember nothing else

  1. AI ⊃ ML. Machine learning is one route to artificial intelligence. Rules and search are others, and they need no training data at all. Every agent in this module was intelligent without learning anything.

  2. An intelligent agent senses its environment, acts on it, and pursues a goal. Formally, it is a function from percepts to actions, judged by a performance measure.

  3. To make an agent plan, describe the problem as a state space (initial state, successor function, goal test) and search it. BFS (a queue) finds the shallowest goal. DFS (a stack) dives deep and uses less memory. Keep a visited set whenever states can repeat.

  4. State spaces explode combinatorially. Even Tic-Tac-Toe has 255,168 games. Every technique in this module (rules, symmetry, heuristics, pruning) is a way to avoid looking at most of them.

  5. A heuristic is an educated guess about how good a state is or how far it is from the goal. It is admissible if it never overestimates the remaining cost, and that depends on which moves are allowed.

  6. A* expands nodes in order of \(f = g + h\) (cost so far plus estimated cost left). With an admissible \(h\) it always finds the shortest path, usually after examining far fewer states than BFS. Greedy search (\(f = h\) only) is faster but can return longer paths.

  7. Minimax handles opponents: MAX takes the highest child value, MIN the lowest, and values flow up from the leaves. On Tic-Tac-Toe it plays perfectly, and the game is a draw with best play on both sides.

  8. Alpha-beta pruning returns exactly the minimax answer while skipping branches that can't change the decision. It searched about 26× fewer Tic-Tac-Toe positions. Negamax is the same algorithm in one branch, using \(\min(a,b) = -\max(-a,-b)\).

  9. When the game is too big to search to the end (Connect Four, chess), cut the search at a fixed depth and score the leaves with a heuristic. Deeper search beats shallower search, which is why pruning matters.

  10. Read textbooks critically and verify numbers by running code. Several of this chapter's figures and pseudocode were wrong, and only running them showed it.

Glossary

Term Meaning
Artificial intelligence Building systems that behave intelligently, by any method: rules, search or learning.
Machine learning Improving at a task \(T\), measured by \(P\), through experience \(E\) (Mitchell).
Intelligent agent An autonomous system that senses (sensors), acts (actuators) and pursues a goal.
State space Every state a problem can be in, connected by the actions between them.
Successor function Given a state, returns the states reachable in one action.
Search tree The tree of states reached by repeatedly applying the successor function from the start.
BFS / DFS Uninformed searches that visit level by level (queue) or branch by branch (stack).
Combinatorial explosion The rapid, multiplicative growth of the number of states as depth increases.
Heuristic An educated-guess function scoring a state's utility or estimated distance to the goal.
Admissible heuristic One that never overestimates the true remaining cost.
Greedy best-first search Expands the node with the smallest \(h\). Fast, but not guaranteed optimal.
A* Expands the node with the smallest \(g + h\). Optimal when \(h\) is admissible.
Minimax Game-tree search where MAX takes the highest child value and MIN the lowest.
Alpha-beta pruning Minimax that skips branches which can't affect the decision. Same answer, less work.
Negamax Minimax written as one branch, using \(\min(a,b) = -\max(-a,-b)\) for zero-sum games.
Static evaluation Scoring a non-terminal position with a heuristic when the search stops.
